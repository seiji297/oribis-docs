## 1. ジャンル定義

| 項目 | 内容 |
|------|------|
| **日本語ジャンル名** | AIパートナー開発環境 |
| **英語ジャンル名** | AI-Partnered Dev Environment |
| **プロダクト名** | Oribis |
| **ワンフレーズ** | 一人で開発してるのに、チームがいる感覚 |
| **タグライン** | AIチームを雇おう。月給0円、記憶力∞ |

### なぜこのジャンル名か

- 「AIパートナー」= ツールではなく同僚。記憶を持ち、常駐し、会話できる存在
- 「開発環境」= IDEではないが、開発を包括的に支援する環境
- 既存カテゴリ（IDE、Copilot、チャットボット、AIエージェント）のどれにも該当しない新カテゴリ

### 曖昧性への対処

「AIパートナー開発環境」は「AIパートナーを開発する環境」と誤読可能。対処:
- 日本語: サブタイトル・キャッチコピーで補完（「記憶を持つAIの同僚と一緒にモノを作る」）
- 英語: "AI-Partnered"（受動形）で「AIがパートナーになった」と明確化

## 2. キラーユースケース: AI同僚付き個人開発

### コンセプト

個人開発者が Oribis を起動すると、**記憶を持つAIの同僚**がデスクトップに常駐する。チャットで相談、@メンションでタスク指示、PTYで直接操作——全部一つの画面で完結。

### 具体的な体験フロー

```
1. 朝、Oribis起動
   → Anima「おはよう。昨日のAPI修正、テスト通ったよ」
   （前日の作業を記憶している）

2. チャット欄で相談
   → 「認証周りどう実装するのがいいかな」
   → Anima が設計提案（会話モード）

3. 方針決定後、Worker に指示
   → 「@SysDev 認証ミドルウェアを実装して。JWT使って」
   → SysDev Worker が自律的にコード生成・テスト実行

4. Worker作業中もリアルタイム確認
   → チャット欄にWorker出力がインライン表示
   → PTYパネルでraw出力も確認可能

5. 並行して別のタスク
   → 「@AFD バグ#123を調査して」
   → 別の Worker が同時稼働

6. 夕方、進捗確認
   → 「今日なにやった？」
   → Anima が全Workerの作業を要約（記憶から復元）
```

### ターゲットユーザー

**プライマリ**: 個人開発者（ソロ開発者・フリーランス・インディー）
- 一人で全部やる必要がある
- 相談相手がいない
- 作業の引き継ぎ先がない
- 「あの修正いつやったっけ」を頻繁に経験する

**セカンダリ**: クリエイター全般
- AIが何でもやってくれるので、プログラミング経験が浅くても開発可能
- 「全員をクリエイターにする」ビジョンへの入り口

### 競合との差別化

| 特性 | Oribis | Cursor/Windsurf | Devin/OpenHands | Character.AI |
|------|--------|----------------|----------------|-------------|
| **常駐** | ○ デスクトップ常駐 | × 起動時のみ | × タスク単位 | ○ 常時 |
| **記憶** | ○ 長期記憶・忘却曲線 | × セッション限定 | × タスク限定 | △ 限定的 |
| **自律開発** | ○ Worker自律実行 | △ 補完・提案 | ○ 自律実行 | × なし |
| **会話** | ○ 人格・感情あり | × なし | × なし | ○ 会話特化 |
| **アバター** | ○ 3D VRM | × なし | × なし | × テキスト |
| **拡張** | ○ Plugin SDK | × プラグイン | × なし | × なし |
| **ローカル** | ○ デスクトップ | △ デスクトップ | × クラウド | × クラウド |

**Oribisの独自ポジション = 「記憶持ち常駐AIアバター × 自律開発 × 会話」の交差点。ここに居るプロダクトは現時点でゼロ。**

## 4. 現在の機能資産

Oribisは既にキラーユースケースの核となる機能をほぼ実装済み。

### 実装済み機能（コアユースケース対応状況）

| 機能 | 状態 | ユースケースでの役割 |
|------|------|-------------------|
| **Anima System** | ✅ 実装済 | 記憶を持つAIパートナーの基盤。長期記憶・好感度・自己モデル |
| **Worker Manager** | ✅ 実装済 | マルチWorker自律実行。部門構成・タスク委任 |
| **@メンション分類器** | ✅ 実装済 | チャット欄からWorkerへの直接指示ルーティング |
| **Worker直接指示** | ✅ 実装済 | anima_direct_dispatch + cancel。PTY write + イベント記録 |
| **PTYターミナル** | ✅ 実装済 | Worker PTYのリアルタイム表示・直接操作 |
| **Worker出力インライン** | ✅ 実装済 | チャット欄内のWorker出力リアルタイム表示 |
| **3Dアバター** | ✅ 実装済 | VRM/FBX/MMD対応。表情・リップシンク・ポーズ |
| **TTS/ナレーション** | ✅ 実装済 | テキスト音声化・イベントバッチ処理 |
| **Plugin SDK v2** | ✅ 実装済 | TypeScript SDK。BGM・Discord・Google・Blender連携 |
| **MCP Server** | ✅ 実装済 | 外部AI（Claude Code, Codex等）からの接続 |
| **Discord連携** | ✅ 実装済 | Bot統合・チャンネル操作 |
| **Google連携** | ✅ 実装済 | Gmail・Docs等 |
| **スケジューラー** | ✅ 実装済 | 定期タスク自動実行 |
| **Web Remote** | ✅ 実装済 | ブラウザからのリモート操作 |

### 追加実装が必要な項目

| 機能 | 優先度 | 概要 |
|------|--------|------|
| **GitHub連携** | P0 | リポジトリ・Issue・PR連携。開発者にとって必須 |
| **プロジェクトテンプレート** | P1 | 「Webアプリ開発」「ゲーム開発」等のワンクリック環境構築 |
| **進捗ダッシュボード** | P1 | Worker稼働状況・タスク進捗・記憶統計の可視化 |
| **ゼロコンフィグ初回起動** | P0 | 起動→即使える。API Key入力のみで開始 |

## 5. 市場分析

### 競合不在の交差点

```
          記憶持ち常駐
              │
    Character.AI ──┤── Oribis ──── Cursor/Windsurf
    (会話のみ)     │  (唯一の交差点)   (開発のみ)
              │
    Replika ───┤
              │
              └── Devin/OpenHands
                  (自律開発のみ・非常駐)
```

完全一致の競合は現時点でゼロ。ただし各領域で部分的に被る製品は存在。

### 市場規模

- AI開発ツール市場: 急成長（Cursor $100M ARR、2025年）
- 個人開発者: 世界2700万人（GitHub統計）、日本100万人超
- AIコンパニオン市場: Character.AI 月間1800万ユーザー
- **「両方欲しい」市場**: 未認識だが確実に存在

### 普及予測（忖度なし）

**爆発的普及はしない。少なくとも初期は。**

理由:
1. カテゴリが新しすぎる（説明に30秒かかる。Cursorは「AI付きVSCode」で3秒）
2. デスクトップアプリのインストール障壁
3. ターゲット二重性（開発者 × クリエイター）
4. 980円の壁（無料ツールが溢れる中での有料）

**現実的シナリオ**:
- 初年度: 熱狂的ファン50-200人
- 2年目: 口コミで500-1000人
- 転換点: 「Oribisで一人でアプリ作った」動画がバズった時

**刺さる人には深く刺さる**タイプ。広く浅くではなく、狭く深くから。Notionも最初はそうだった。
